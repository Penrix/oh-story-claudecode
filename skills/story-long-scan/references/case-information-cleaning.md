# 榜单 Case 信息清洗

## 目标

清洗不是改写，也不是玩法研究。

只做两个动作：

```text
原始 Case
├─ 高置信度没有信息含量 → 清出主动检索榜单
└─ 有信息 / 疑似有信息 / 拿不准 → 保留
```

保留的 Case 中，**原书名和原简介全文不改**。

## 什么叫“没有信息含量”

典型是只给通用结果和宣传套话，却没有增加关于这本书的具体事实：

```text
少年意外穿越异界
→ 经历无数冒险
→ 结识伙伴
→ 战胜强敌
→ 一步步走上巅峰
```

这些句子换一本书仍几乎成立，不告诉我们这本书具体有什么。

可以清理的对象包括：

- 纯宣传口号；
- 纯“穿越—冒险—成长—巅峰”套话；
- 只有泛化题材词、没有具体人物/关系/条件/行动/设定的简介；
- 明显占位、作者说“不会写简介请看正文”而正文前没有其他具体信息的简介。

## 什么应当保留

只要简介增加了具体事实，就倾向保留。包括但不限于：

- 特殊能力、金手指、规则、限制；
- 具体身份、处境、目标；
- 具体人物关系与选择；
- 具体资源、取得方式、经营对象；
- 有价格的世界条件或设定；
- 明确的行动方式、爽点或人生玩法；
- 暂时看不懂，但疑似承重的具体信息。

**保守删除：确定没信息才删；拿不准就留。**

不要因为简介短、只有一句、套不进某个公式，就删除。

## 一个辅助观察，不是唯一标准

可以用这个问题帮助判断简介是否提供了可运行信息：

> 这个简介里面，什么东西“进去”，经过什么动作以后，变成了什么“出来”？

例如：

```text
别人对我的认知
→ 被系统兑现
→ 变成对应真实能力
```

或者：

```text
我击败某个角色
→ 触发掉落
→ 得到对方拥有的能力
```

但这个公式**不是准入条件**。人物关系、身份玩法、经营目标、世界条件等信息即使不能压成“进—动作—出”，只要有具体信息，同样保留。

## 可选检索注释

为了提高后续检索，可以在原简介下面追加非常短的注释。

注释只是路标，不是新本体，不要求每本都有，也不要求统一填满字段。

示例：

```markdown
#### 《原书名》

原简介全文，不改。

【检索注释】
认知 → 兑现 → 能力
```

规则：

- 不覆盖、不摘要替换原简介；
- 不为了写注释而猜；
- 注释可以随着认识更新；
- 原始简介始终是证据主体。

## 采集与清洗的关系

```text
采集
→ 尽量广地拿到真实书名 + 完整原简介
→ 不提前判断玩法

清洗
→ 删除高置信度纯废话
→ 保留有信息和疑似有信息的 Case
→ 原文不动，可选加检索注释
```

当前采集产品方向：

```text
第一优先：飞卢 + 番茄男频
第二优先：起点 + 刺猬猫
```

原因是飞卢、番茄男频往往把卖点写得更直白，更适合作为高信息密度简介来源。飞卢 Runtime 采集器尚未接入时，不得把“优先方向”写成“已经实现”。


## 排除项的持久化

人工判定为高置信度低信息的 Case 记录在：

```text
data/story-cases/清洗排除.jsonl
```

排除键使用：

```text
归一化书名 + 当前原简介 SHA-256
```

因此清掉的是**当前这版低信息简介**，不是给整本书永久判死刑。以后平台若更新简介，原文发生变化，就不会命中旧指纹，会重新进入候选池接受新的信息判断。

## 2026-10-11 当前执行裁决与第一轮结果

这份清洗规则只有一个用途：**为后续检索腾出空间，保留有实际信息的原始书名与原始简介。** 用户明确拒绝把榜单清洗变成玩法研究、语义蒸馏或格式改写。

执行只有两个动作：

- 高置信度的纯废话、纯口号、纯作者广告、空泛成长结果 → 从主动榜单移出，并以「原书名 + 当前简介指纹」记录，防止同版文本下次重入；
- 有具体信息、疑似有具体信息、判断不准 → 原样保留。

「什么进去—经过什么动作—什么出来」仅用于辅助寻找信息，**不是必须满足的公式**。没有明显的输入输出也可能存在重要人物关系、世界条件、商业卖点；不能因此删除。

保留数据的书名、简介逐字不变。可选检索注释不做理论定论、不强制填写、不参与替换原文。为了避免改变已有 Case，本轮不批量添加注释。

首次清洗在主池 2,620 条之上，明确移出 6 条同版低信息简介，保留 2,614 条。既有 3 条排除指纹继续有效；此次新增 6 条，排除记录共 9 条。记录详见 `data/story-cases/清洗排除.jsonl`。这是一轮**高置信度初筛，不等于逐条审定 2,614 条都高价值**，更不能由删除比例倒推整个池子的质量。

特别保留反例：《玄鉴仙族》《大赤仙门》虽然含有传统宣传词，仍能从简介发现具体的镜子传道、观主继位、传承经营等事实；不能见到「波澜壮阔」「登仙」就删。

## 2026-10-11 维护接手核查断点

本节是对 GitHub `main`（核查时最新提交 `cf60d2d`）的现状复核；不是新理论或已经完成的全量清洗验收。

- **主动主池**：直接读取 `data/story-cases/榜单数据.jsonl` 的 Git Blob，核对为 **2,598 条**；逐行均有书名和非空简介，按归一化书名未发现重复。对应 Markdown 与 JSONL 均在仓库。此事实只说明技术完整性，不代表 2,598 条均已人工审定有价值。
- **排除记录**：`data/story-cases/清洗排除.jsonl` 当前为 **25 条**，其中三条早期记录、首轮新增六条、第二轮新增十六条。是“原书名 + 当时原简介指纹”的版本性排除，不应永久封禁整本书。
- **起点待补**：`data/story-cases/起点待补简介.jsonl` 当前 **541 条**，其中 **146 条的 title 是「WAF拦截页面」**；**531 条 first_seen 为 2026-10-08**；最高失败尝试数 **47**。待补数不等于有效可用 Case 数，也不说明当前已经突破反爬。应重点排查占位标题和重复失败，而非无意义地反复重试。
- **采集能力**：番茄、起点、刺猬猫已有对应采集器；**飞卢尚未接入当前工作流**。本轮只核查仓库，不视为已完成新一轮真实网站抓取。
- **污染源仍未根治**：复合女频标签匹配的 JavaScript 正则语法已在 `cf60d2d` 修复；但这只是简介中的明确标签检查。起点关联书单尚缺可核验的逐作品男频频道限制，最终 JSONL 不保存来源/频道，无法从主池反推出每条混入路径。不可把“修复正则”等同“堵住采集入口”。
- **清洗边界**：只能对高置信度无信息或明确女频污染作排除；任何有信息、疑似有信息、男性主角反穿女频题材等均应以具体简介证据判断，拿不准就保留。保留项的书名与简介不改写；标注不替换原文。

- **尚需修复的原文保真细节**：Builder 目前会通过 `normalizeIntro` 折叠连续空格、合并多余空行、去掉首尾空白；这与“简介原文不改”的严格字面要求不完全一致。尚未完成修复及回归，不能因为内容字词相近就宣称逐字/逐格式保真。处理时应以平台取得的原始完整简介为证据，不用猜测修复既有数据。
- **下一个执行断点**：先延续主池的保守逐条清洗，并保留排除证据；同时独立修复入口的频道识别、WAF 待补质量、飞卢采集。改动脚本后再跑回归和重新合并，不将审计文字冒充数据处理完成记录。
