# 榜单 Case 信息清洗

## 目标

清洗不是改写，也不是玩法研究。

只做两个动作：

```text
原始 Case
├─ 高置信度没有信息含量 → 清出主动检索榜单
└─ 有信息 / 疑似有信息 / 拿不准 → 保留
```

保留的 Case 中，**原书名和原简介全文不改**。

## 什么叫“没有信息含量”

典型是只给通用结果和宣传套话，却没有增加关于这本书的具体事实：

```text
少年意外穿越异界
→ 经历无数冒险
→ 结识伙伴
→ 战胜强敌
→ 一步步走上巅峰
```

这些句子换一本书仍几乎成立，不告诉我们这本书具体有什么。

可以清理的对象包括：

- 纯宣传口号；
- 纯“穿越—冒险—成长—巅峰”套话；
- 只有泛化题材词、没有具体人物/关系/条件/行动/设定的简介；
- 明显占位、作者说“不会写简介请看正文”而正文前没有其他具体信息的简介。

## 什么应当保留

只要简介增加了具体事实，就倾向保留。包括但不限于：

- 特殊能力、金手指、规则、限制；
- 具体身份、处境、目标；
- 具体人物关系与选择；
- 具体资源、取得方式、经营对象；
- 有价格的世界条件或设定；
- 明确的行动方式、爽点或人生玩法；
- 暂时看不懂，但疑似承重的具体信息。

**保守删除：确定没信息才删；拿不准就留。**

不要因为简介短、只有一句、套不进某个公式，就删除。

## 一个辅助观察，不是唯一标准

可以用这个问题帮助判断简介是否提供了可运行信息：

> 这个简介里面，什么东西“进去”，经过什么动作以后，变成了什么“出来”？

例如：

```text
别人对我的认知
→ 被系统兑现
→ 变成对应真实能力
```

或者：

```text
我击败某个角色
→ 触发掉落
→ 得到对方拥有的能力
```

但这个公式**不是准入条件**。人物关系、身份玩法、经营目标、世界条件等信息即使不能压成“进—动作—出”，只要有具体信息，同样保留。

## 可选检索注释

为了提高后续检索，可以在原简介下面追加非常短的注释。

注释只是路标，不是新本体，不要求每本都有，也不要求统一填满字段。

示例：

```markdown
#### 《原书名》

原简介全文，不改。

【检索注释】
认知 → 兑现 → 能力
```

规则：

- 不覆盖、不摘要替换原简介；
- 不为了写注释而猜；
- 注释可以随着认识更新；
- 原始简介始终是证据主体。

## 采集与清洗的关系

```text
采集
→ 尽量广地拿到真实书名 + 完整原简介
→ 不提前判断玩法

清洗
→ 删除高置信度纯废话
→ 保留有信息和疑似有信息的 Case
→ 原文不动，可选加检索注释
```

当前采集产品方向：

```text
第一优先：飞卢 + 番茄男频
第二优先：起点 + 刺猬猫
```

原因是飞卢、番茄男频往往把卖点写得更直白，更适合作为高信息密度简介来源。飞卢 Runtime 采集器尚未接入时，不得把“优先方向”写成“已经实现”。


## 排除项的持久化

人工判定为高置信度低信息的 Case 记录在：

```text
data/story-cases/清洗排除.jsonl
```

排除键使用：

```text
归一化书名 + 当前原简介 SHA-256
```

因此清掉的是**当前这版低信息简介**，不是给整本书永久判死刑。以后平台若更新简介，原文发生变化，就不会命中旧指纹，会重新进入候选池接受新的信息判断。
